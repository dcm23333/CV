# AR 升级区颜色识别（ENTERPRIZE RM2027 内部赛）

仓库：<https://github.com/dcm23333/CV>　（SSH：`git@github.com:dcm23333/CV.git`）

识别 AR 升级区 **4 个矿石位**，按摄像头视角 **从左到右** 一一对应，判定每个位置是
**绿色 = 空位** 还是 **红色/蓝色 = 有矿石**，并通过 **JC24B 无线串口模块** 把结果发给 AR 主控。

规则依据（手册 2.2.5 / 3.4.2）：

| 标识 | 含义 |
|---|---|
| 绿色塑料板 | 空位，**无矿石** |
| 红色 / 蓝色塑料板 | **有矿石**（红或蓝取决于队伍所在半场） |

识别成功标准：UI 明确显示 4 个结果、处理帧率 **≥ 30fps**、维持 **5 秒** 无丢失/误识别（+10 分）。

## 3. 识别流程

1. **全局搜索**：HSV 二值化 → 形态学清洗 → 轮廓筛选（面积/长宽比/凸包密实度）→ 用
   「面积一致 + 同一水平线 + 间距均匀」打分挑出最像 4 块色板的一组。
2. **锁定**：连续 `lock_frames`(8) 帧都稳定找到 4 个、且中心漂移小于 `max_drift`，才锁定。
   锁定后只在上一帧位置附近跟踪，避免被场地其它颜色干扰；丢失超过 `miss_frames` 帧自动重搜。
3. **从左到右排序**：锁定与跟踪每帧都按中心 x 排序，槽位 1..4 恒等于画面最左到最右。
4. **颜色判定**：在 ROI 内统计各颜色像素占比，取最大者；占比低于 `min_coverage`(12%) 判为未识别。
   绿 → `EMPTY`，红/蓝 → `OCCUPIED`。
5. **时间滤波**：9 帧众数投票，平票时偏向已知状态，避免 `UNKNOWN` 卡死。
6. **稳定判定**：4 个槽位全部非 `UNKNOWN` 且各自连续保持 ≥ 5 秒 → 判定识别成功（画面底部横幅提示）。

> 性能：检测在 `--detect-width 640` 的缩略图上进行，绘制仍在原分辨率，轻松满足 ≥30fps。

## 4. JC24B 无线串口接口

JC24B 是 **透明传输** 的 2.4GHz 无线串口模块，串口侧就是普通 UART：

```
CV 端(PC) --USB转串口--> JC24B )))  无线  ((( JC24B --UART--> AR 主控(STM32)
```

### 帧格式（9 字节）

| 字节 | 含义 |
|---|---|
| 0 | `0xAA` 帧头 |
| 1 | `0x55` 帧头 |
| 2 | `CMD = 0x10` 槽位颜色状态 |
| 3–6 | `S1 S2 S3 S4`：**从左到右** 4 个矿石位，`0`=空(绿) `1`=有(红/蓝) `2`=未识别 |
| 7 | `SEQ` 帧序号 0–255 回绕 |
| 8 | `CRC8`（poly `0x07`，覆盖字节 2–7） |

示例（从左到右 空/有/空/有，SEQ=7）：

```
AA 55 10 00 01 00 01 07 F6
```

### 发送策略

- **状态变化立即发**，无变化时按 `--heartbeat`（默认 500ms）周期心跳，对端可据此判掉线
- 串口异常自动累计失败并尝试重连，不会让主循环崩掉
- 没接模块时是 **dry-run**：正常跑视觉，只是不占串口，方便单独调视觉

### 代码里怎么调用

```python
from radio import JC24BLink
from config import RadioConfig

link = JC24BLink(RadioConfig(enabled=True, port="COM3", baudrate=115200))
link.open()
link.send_slots([0, 1, 0, 1])   # 从左到右 4 个槽位；返回是否写入成功
link.close()
```

联调时不想碰真实串口，用 `DummyLink`，它会记录所有发出的帧：

```python
from radio import DummyLink
link = DummyLink()               # link.frames 里是每一帧 bytes
```

### 对端（AR 主控）解析要点

按 `AA 55` 做帧同步 → 取 9 字节 → 校验 CRC8 → 读 `S1..S4`。
建议对端连续 1 秒收不到心跳就认为 CV 掉线，回退到安全策略。

## 5. 现场标定（重要）

灯光一变 HSV 就漂，上场前务必现场标定：

```bash
python main.py --camera 0 --tune
```

拖 `HSV Tuner` 窗口的滑块，直到画面里 4 个框都稳定出现、覆盖率高且颜色正确，
再把稳定值抄回 `config.py` 的 `HSV_RANGES`（或直接在 `config.py` 里改）。

实测参考（室内灯光、塑料板偏浅）：绿色板 `H≈61 S≈49 V≈216`、蓝色板 `H≈101 S≈125 V≈240`。
**绿色饱和度常常只有 45~50，所以 green 的 Smin 单独放低到 30**；
若照搬红蓝的 Smin≈70，浅绿会整块漏检（这是第一版实测踩过的坑）。

自动搜索一直锁不上时的兜底：按 `m` 进入手动 ROI 模式，在画面上**从左到右**依次拖 4 个框，
框完立即生效并写死跟踪位置（此后不再做全局搜索）。机位固定后这是最稳的方式；
配合 `l` 导出 `roi.json`，下次直接 `--roi-file captures/roi.json` 启动。

信息栏里的 `cand=N/4` 是当前帧找到的候选框数量：一直小于 4 说明某块板 HSV 没盖住，
去调参窗口把对应颜色的 Smin/Vmin 放低。

常用调节项：

| 参数 | 说明 |
|---|---|
| `min_area` / `max_area` | 色板候选面积范围，按相机到升级区的距离调 |
| `min_coverage`(12%) | ROI 内颜色占比门槛，色板小而远时调低 |
| `min_solidity` | 滤掉细长噪点 |
| `roi_scale` | 判定框相对色板框的扩张系数 |
| `stable_seconds` | 默认 5.0，与规则一致 |

## 6. 后续扩展

- **角度识别（+30 分）**：红/蓝位置的角度板会随机侧斜 ±30°，绿位正对。
  协议里已留好扩展空间，加一条 `CMD` 即可携带 4 个角度值，`Protocol.RESERVED` 就是预留字节。
- **双向通讯**：规则要求 AR 与 CV 可双向通讯。当前只做了 CV → AR 单向，
  如需接收 AR 的指令，在 `radio.py` 里加一个读线程 + 同样的帧解析即可。
